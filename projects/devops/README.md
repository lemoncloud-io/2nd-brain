# devops — 개발 작업 진입 절차

`CLAUDE.md` § Development Work 가 개발 작업 전에 이 문서를 읽으라고 가리킨다.
이 문서는 **기본 절차**다. 조직에 자기 개발 지침(사용 언어·프레임워크·저장소 규칙·배포 방식)이 있으면
이 문서를 그 지침으로 바꾸거나, 아래 순서에 그 지침으로 가는 포인터를 더한다.

## 왜 있나

에이전트(Claude 등)에게 "데이터를 처리해서 저장해 줘"라고만 하면, 매번 다른 구조를 고르거나 서버 한 대를 계속 켜 두는
구성을 만들기 쉽다. 이 문서는 요청을 받았을 때 **먼저 어디서 돌릴지 가르고**, 서버가 필요한 처리는 **검증된 표준 구조**로
보내도록 순서를 고정한다. 목적은 설명이 아니라 바로 쓸 수 있게 하는 것이다.

## 진입 순서

1. **어디서 돌릴지 가른다.**

   | 작업 | 어디서 | 예 |
   |---|---|---|
   | 화면을 만들어 보기·내 PC에서 쓰는 도구·한 번 돌리는 분석 | **로컬** | React + Vite 화면, 스크립트, 노트북 |
   | 파일이 들어올 때마다 자동 처리 · 쌓이는 데이터 저장·검색 · 내 PC가 꺼져도 돌아야 함 · 대용량 | **AWS 서버리스** | 업로드된 문서 정리, 로그 적재·검색, 주기 데이터 집계 |

   로컬 작업은 이 볼트의 일반 규칙대로 하고, 결과물은 해당 프로젝트 폴더에 둔다. 아래 2번부터는 서버리스 작업의 순서다.

2. **표준 구조를 쓴다** — [aws-serverless](../aws-serverless/README.md)

   ```
   원본 데이터 → S3 업로드 → (S3 이벤트) Lambda 처리 → DynamoDB 저장
                                                └ (검색·집계가 필요하면) Stream → Lambda → OpenSearch Serverless
   ```

   - 원본은 **먼저 S3에 올린다.** 처리 Lambda는 S3 이벤트로 돈다 — 요청마다 서버를 부르지 않는다.
   - 저장은 DynamoDB. 검색·집계·시계열 조회가 필요할 때만 OpenSearch를 붙인다(OpenSearch는 켜 두기만 해도 시간당 과금).
   - 이 구조로 안 되는 요구(업무 API, 일정 실행, 대시보드)는 범위 밖이다 — 그때는 따로 설계한다.

3. **계정과 키를 준비한다** — 처음 한 번.
   1. [계정 가입과 가입 직후 설정](../aws-serverless/guides/01-aws-account-setup.md)
   2. [배포 키 발급](../aws-serverless/guides/02-restricted-key.md) — 배포는 관리자 키가 아니라 **정책 3개로 묶은 배포 키**로만 한다.
   3. `verify.sh` 로 키를 검증한다 — 전부 PASS 여야 다음 단계로 간다.

4. **데이터부터 정리한다** — [As-Is/To-Be 양식](../aws-serverless/guides/as-is-to-be.md).
   데이터 형식, 생성 주기와 양(하루 몇 건, 건당 크기), 누가 보는지를 적는다. 이 값이 저장 구조(키 설계)와 비용 추정의 입력이다.

5. **스킬 순서대로 배포·확인한다** — `aws-serverless/config/skills/`.
   `aws-s3-ingest` → `aws-lambda-deploy` → `aws-dynamodb-stream` → `aws-opensearch`. 각 스킬의 확인 단계(파일 1개 업로드 → 저장 1행 →
   검색 1건)를 통과해야 끝난다.

6. **결과를 남긴다.** 무엇을 배포했고 무엇을 확인했는지를 해당 프로젝트 README 의 Log 에 적는다.

## 원칙

- **키·계정 ID·암호는 볼트에 쓰지 않는다.** 문서·로그·커밋 어디에도. 에이전트 대화창에도 붙여 넣지 않는다.
- **확인 없이 끝내지 않는다.** 배포했다는 말이 아니라 업로드 → 저장 → 검색이 실제로 된 결과로 끝낸다.
- **비용 방어는 예산 알림이다.** 배포 키 정책이 못 막는 비용(DynamoDB 용량, Lambda 실행량)이 있다 — 계정 준비 단계의 예산 알림을 꼭 건다.
- **반복되는 절차는 스킬로 만든다.** 같은 요청을 두 번 이상 받으면 `projects/<name>/config/skills/` 에 스킬로 적는다.
  Claude Code 가 자동으로 찾게 하려면 폴더형(`<name>/SKILL.md`)으로 만들고 `.claude/skills/<name>` 에 상대 경로 심링크를 둔다
  (루트 `README.md` § 스킬의 폴더형 스킬과 같은 방식).
