# 오케스트레이터-전문가 에이전트 분리

## Summary

모델 하나가 채팅 창 하나 안에서 모든 일을 하게 만들지 않고, 역할마다 가장 잘 맞는 도구를 따로 배치하는 구성이다.
항상 켜져 있는 오케스트레이터가 요청을 받아 직접 처리할지 전문가 에이전트에게 넘길지 정하고, 전문가의 결과를 다시 확인해
보고한다. 원문은 [[wiki/hermes-agent|Hermes Agent]]를 오케스트레이터로, OpenAI Codex를 오케스트레이터의 주 모델로,
Claude Code를 구독 기반 코딩 전문가로, Telegram을 원격 인터페이스로 쓰는 개인 설정을 소개한다.

## Details

**역할 배치 (원문 사례)**

| 역할 | 담당 | 하는 일 |
| --- | --- | --- |
| 오케스트레이터·자동화 계층 | Hermes Agent | 메모리·도구·예약 작업·메시징 보유, 셸·파일·cron·메일 실행, 작업 조정 |
| 오케스트레이터의 주 모델 | OpenAI Codex | 일반 대화 조정과 도구 사용 |
| 코딩 전문가 | Claude Code | 범위가 정해진 코딩 작업의 작성·검토·수정 |
| 실행 환경 | 로컬 머신(상시 가동 Linux 박스·미니 PC 등) | 도구가 실제로 도는 곳 |
| 원격 인터페이스 | Telegram | 어디서든 오케스트레이터에 지시 |

**흐름**

1. 사용자가 오케스트레이터에게 원하는 것을 말한다.
2. 오케스트레이터가 직접 처리할지, 코딩 부분을 전문가에게 넘길지 정한다.
3. 전문가가 코드를 작성·검토·수정한다.
4. 오케스트레이터가 결과를 확인하고, 간단한 테스트를 돌리고, 시스템에 연결한 뒤 보고한다.

**위임 방식** — 별도 래퍼 없이 오케스트레이터가 `claude` CLI를 서브프로세스로 호출한다(`claude -p "<작업>" --max-turns 10`).
긴 작업은 tmux 세션에서 Claude Code를 대화형으로 띄우고 오케스트레이터가 지켜본다. 원문 작성자는 헤드리스 호출의 과금
변화(아래) 이후 tmux 쪽으로 옮기는 중이라고 적었다.

**설치 함정** — 오케스트레이터가 관리하는 Node가 `claude` 바이너리를 기본 `PATH` 밖에 설치할 수 있다. 원문은 셸 설정에
경로를 추가하고 `~/.local/bin/`에 심볼릭 링크를 걸어 해결했다.

**로컬 모델 대체 시도** — 성능이 낮은 하드웨어에서 Ollama로 로컬 LLM을 돌려 본 결과 동작은 했지만 에이전트 전체 용도로는
너무 느렸다고 한다(작성자 경험담, 측정치 없음).

**비용 경로 주의** — 원문의 요지는 구독 인증(OAuth)으로 두 도구를 쓰면 토큰당 과금이 없고, API 키를 직접 연결하면 과금이
시작된다는 것이다. 다만 원문 2026-05-14 편집분은 2026-06-15부터 `claude -p`·Agent SDK 같은 프로그래밍 방식 호출이 구독 풀에서
분리돼 별도 월 크레딧(API 요금 기준)으로 계량된다고 적고, 헤드리스 모드가 API 요금으로 넘어가는 버그 보고와 페이로드 속
하네스 문자열이 제3자 하네스 사용으로 분류됐다는 댓글 주장도 덧붙인다. **모두 원문 작성자·댓글의 주장이며 공식 문서로
확인하지 않았다.** 이 구성을 쓴다면 `claude /status`로 실제 인증 경로를 확인하고, API 키를 쓰게 되면 제공업체 결제 화면에서
월 상한을 먼저 정하라는 것이 원문의 권고다.
